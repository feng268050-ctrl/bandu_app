## 1. 背景与现状

当前 App 的核心定位是错题整理与复习。“题集”在现有需求中表示错题集合，“错题”表示题集中的单条学习记录。现有能力覆盖拍照或从相册选择单道错题、AI 分析题目/答案/解析、保存到题集，以及围绕错题进行 AI 辅导、变式练习和练习批改。

用户提出的新需求是：上传一套 PDF 格式的题集，导入完成后随机抽出若干题生成考卷；如果题集包含答案，用户完成一题后立即显示该题答案，并进行即时批改。

该需求当前不在首版范围内。现有 App 不支持 PDF 导入、批量拆题、题目与答案匹配、独立题库管理或随机组卷。因此需要新增“题库”能力，并与现有“错题题集”保持概念隔离。

## 2. 目标

### 2.1 用户目标

1. 用户可以上传 PDF 题集。
2. App 可以从 PDF 中提取题目、答案和解析。
3. 用户可以复核自动识别结果，修正拆题或答案匹配错误。
4. 导入完成后，PDF 内容形成独立题库。
5. 用户可以从题库中按条件随机抽题生成考卷。
6. 用户完成一题后立即看到该题答案和解析。
7. App 可以对用户答案进行本地或 AI 批改。

### 2.2 产品边界

1. v1 不追求完全自动化导入，必须保留人工复核。
2. v1 不把 PDF 题库直接混入现有错题集合。
3. v1 继续保持本地优先，不引入账号、云同步或后端服务。
4. PDF 题库可产生练习记录，也可将用户答错的题目手动或自动转为错题，但这属于后续扩展，不作为 v1 必需能力。

## 3. 目标流程

### 3.1 PDF 导入流程

1. 用户进入“导入 PDF 题集”入口。
2. 用户通过系统文件选择器选择 PDF。
3. App 创建导入任务，并保存 PDF 基本信息。
4. App 优先解析 PDF 文本层。
5. 如果 PDF 无可用文本层或文本质量过低，则将页面渲染为图片，并通过 OCR 或 AI 视觉识别。
6. App 按题号、版式和语义结构拆分题目。
7. App 识别答案区、解析区和参考答案页。
8. App 建立题目与答案/解析的匹配关系。
9. App 展示导入复核页，用户检查题目、答案、解析、来源页码和异常项。
10. 用户确认后，App 将题目写入独立题库。

### 3.2 随机组卷流程

1. 用户进入题库详情。
2. 用户点击“生成考卷”。
3. 用户选择题数、范围、标签、难度和是否包含已练习题。
4. App 根据条件查询候选题。
5. 如果候选题不足，App 显示明确提示，不创建空考卷。
6. App 使用随机种子抽取题目并保存题目顺序。
7. App 创建考卷会话并进入做题页面。

### 3.3 逐题作答与即时批改流程

1. App 展示当前题目。
2. 用户提交答案。
3. 如果题目有标准答案，App 立即展示答案和解析。
4. 客观题优先使用本地规则判定正确或错误。
5. 主观题调用 AI 批改，结果为“正确”“错误”“待复核”之一。
6. AI 批改失败时保留用户答案，允许重试或标记为待复核。
7. 用户进入下一题。
8. 考卷完成后，App 展示答题结果、正确率、待复核数量和错题列表。

## 4. 核心设计

### 4.1 新增“题库”概念

题库是从 PDF 或后续其他批量来源导入的完整题目集合。题库与现有错题题集分离：

| 概念 | 用途 | 来源 | 是否表示用户错题 |
| --- | --- | --- | --- |
| 错题题集 | 整理用户错题 | 拍照、相册、手动保存 | 是 |
| PDF 题库 | 保存导入题目 | PDF 导入 | 否 |

这种分离可以避免把未做过的题误认为错题，也能让统计、筛选和复习语义保持清晰。

### 4.2 数据模型

#### QuestionBank

保存一个导入题库的元信息。

| 字段 | 说明 |
| --- | --- |
| `id` | 题库 ID |
| `name` | 题库名称，默认取 PDF 文件名 |
| `source_type` | 来源类型，v1 固定为 `PDF` |
| `source_file_name` | 原始文件名 |
| `subject` | 学科，可由用户设置或 AI 推断 |
| `question_count` | 已确认题目数量 |
| `import_status` | `PENDING`、`REVIEW_REQUIRED`、`IMPORTED`、`FAILED` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

#### BankQuestion

保存题库中的单道题。

| 字段 | 说明 |
| --- | --- |
| `id` | 题目 ID |
| `bank_id` | 所属题库 ID |
| `stem` | 题干 |
| `options` | 选项，客观题可用 |
| `answer` | 标准答案，可为空 |
| `analysis` | 解析，可为空 |
| `question_type` | `SINGLE_CHOICE`、`MULTIPLE_CHOICE`、`FILL_BLANK`、`SUBJECTIVE`、`UNKNOWN` |
| `difficulty` | `EASY`、`MEDIUM`、`HARD`、`CHALLENGE`、`UNKNOWN` |
| `tags` | 知识点标签 |
| `source_page` | PDF 来源页码 |
| `source_rect` | 页面截图区域，可为空 |
| `source_image_uri` | 题目截图，可为空 |
| `review_status` | `AUTO_CONFIRMED`、`NEEDS_REVIEW`、`USER_CONFIRMED` |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

#### ExamSession

保存一次随机组卷。

| 字段 | 说明 |
| --- | --- |
| `id` | 考卷会话 ID |
| `bank_id` | 来源题库 ID |
| `title` | 考卷标题 |
| `seed` | 随机种子 |
| `question_count` | 题目数量 |
| `status` | `IN_PROGRESS`、`COMPLETED` |
| `created_at` | 创建时间 |
| `completed_at` | 完成时间，可为空 |

#### ExamAttempt

保存用户对单题的作答和批改结果。

| 字段 | 说明 |
| --- | --- |
| `id` | 作答记录 ID |
| `session_id` | 考卷会话 ID |
| `question_id` | 题目 ID |
| `order_index` | 题目顺序 |
| `user_answer` | 用户答案 |
| `answer_revealed` | 是否已显示标准答案 |
| `grading_result` | `CORRECT`、`INCORRECT`、`NEEDS_REVIEW`、`NOT_GRADED` |
| `grading_source` | `LOCAL`、`AI`、`MANUAL`、`NONE` |
| `grading_feedback` | 批改说明，可为空 |
| `submitted_at` | 提交时间，可为空 |

## 5. PDF 解析策略

### 5.1 文本层优先

对于包含文本层的 PDF，App 应优先使用文本提取，原因是速度快、成本低、可减少 AI 调用。文本提取后仍需做结构分析，包括题号识别、选项识别、答案区识别和解析区识别。

### 5.2 扫描版 PDF

如果 PDF 页面主要是图片，App 将页面渲染为图片后处理：

1. 低分辨率页面图用于预览。
2. 高分辨率页面图用于 OCR 或 AI 视觉识别。
3. 题目截图区域用于后续追溯和数学图形展示。

扫描版 PDF 的识别结果必须进入复核流程，不能直接静默导入为已确认题目。

### 5.3 题目拆分

题目拆分按以下优先级执行：

1. 规则识别：题号模式，如 `1.`、`1、`、`（1）`、`第 1 题`。
2. 版式识别：题目前后间距、选项区域、分页边界。
3. AI 结构化解析：当规则无法稳定拆分时，调用 AI 返回结构化题目列表。
4. 人工复核：无法确认的题目进入异常项列表。

### 5.4 答案匹配

答案匹配按以下优先级执行：

1. 同页题后答案。
2. 章节末尾答案。
3. PDF 末尾参考答案页。
4. 按题号匹配。
5. AI 辅助匹配。
6. 人工确认。

如果题目和答案无法可靠匹配，题目可以导入，但 `answer` 为空，并标记为 `NEEDS_REVIEW`。

## 6. UI 与交互

### 6.1 入口

建议在“新增”入口中增加“导入 PDF 题集”。该入口与“拍照错题”“从相册选择”并列，但进入独立题库导入流程。

### 6.2 导入复核页

导入复核页至少包含：

1. 导入进度。
2. 成功识别题目数量。
3. 需要复核题目数量。
4. 题目与答案匹配状态。
5. 原 PDF 页面预览。
6. 题干、答案、解析编辑入口。
7. “确认导入”按钮。

未复核异常项时，允许用户保存为草稿，但不允许标记为完整导入。

### 6.3 题库页

题库页展示：

1. 题库名称。
2. 题目数量。
3. 来源 PDF 文件名。
4. 导入状态。
5. 最近练习时间。
6. “生成考卷”入口。

### 6.4 做题页

做题页采用逐题模式：

1. 展示题目、选项和必要图片。
2. 用户输入或选择答案。
3. 点击提交后锁定当前答案。
4. 立即显示标准答案和解析。
5. 显示批改结果。
6. 用户点击进入下一题。

逐题模式可以降低长考卷状态恢复复杂度，也符合“完成一题就显示一题答案”的需求。

## 7. 批改策略

### 7.1 客观题本地批改

单选、多选和填空题优先本地批改。批改前应做答案标准化：

1. 去除首尾空白。
2. 统一大小写。
3. 去除常见分隔符差异。
4. 多选题按选项集合比较。

### 7.2 主观题 AI 批改

主观题使用 AI 批改。请求上下文包含题干、标准答案、解析和用户答案。AI 必须返回三态结果：

1. `CORRECT`
2. `INCORRECT`
3. `NEEDS_REVIEW`

AI 返回无效格式、网络失败或超时时，保留用户答案，结果标记为 `NEEDS_REVIEW`，并允许重试。

### 7.3 无标准答案题目

如果题目没有标准答案：

1. 页面显示“暂无标准答案”。
2. 用户可选择请求 AI 解题和批改。
3. AI 结果不得自动写回标准答案，除非用户确认。

## 8. 非功能要求

1. PDF 导入任务可取消。
2. 导入失败不得产生半完成题库；草稿题库必须有明确状态。
3. PDF 页面渲染和 OCR/AI 处理不得阻塞主线程。
4. 大 PDF 应分页处理，避免一次性加载全部页面图片。
5. 原始 PDF 与页面截图只保存在 App 私有目录。
6. AI 请求前沿用现有隐私提示，明确告知将发送 PDF 页面、题目文本或用户答案。
7. 删除题库时必须同步删除不再引用的 PDF 页面缓存和截图文件。

## 9. 分期实现

### Phase 1：基础导入与手动复核

1. 新增题库模型和题库列表。
2. 支持选择 PDF 并生成页面预览。
3. 支持用户手动拆题、录入答案和解析。
4. 支持确认导入为题库。
5. 支持从题库随机抽题生成考卷。

### Phase 2：自动解析

1. 支持 PDF 文本层提取。
2. 支持扫描版页面 OCR 或 AI 视觉识别。
3. 支持题号、选项、答案和解析自动识别。
4. 支持异常项复核。

### Phase 3：即时批改

1. 支持逐题作答。
2. 支持提交后显示答案和解析。
3. 支持客观题本地批改。
4. 支持主观题 AI 批改。
5. 支持考卷结果汇总。

### Phase 4：学习闭环增强

1. 支持将答错题目转入错题题集。
2. 支持题库练习统计。
3. 支持按章节、标签、难度和历史正确率智能组卷。
4. 支持复习间隔推荐。

## 10. 测试计划

### 10.1 PDF 导入

1. 带文本层 PDF 可以导入并提取文本。
2. 扫描版 PDF 可以生成页面预览。
3. 拆题失败时进入人工复核。
4. 答案匹配失败时不得静默保存为已匹配题目。
5. 用户取消导入后不留下已完成题库。
6. 导入失败后可以重试。

### 10.2 随机组卷

1. 指定题数后生成正确数量题目。
2. 同一考卷会话内题目顺序稳定。
3. 题库题数不足时给出明确提示。
4. 过滤条件无结果时不创建空考卷。
5. App 重启后未完成考卷可以继续。

### 10.3 即时批改

1. 有标准答案的题目提交后立即显示答案。
2. 客观题可以判定正确或错误。
3. 多选题不受用户选项顺序影响。
4. 主观题 AI 批改失败时保留用户答案并允许重试。
5. 无标准答案题目显示“暂无标准答案”或走 AI 解题策略。
6. 用户完成整卷后可以查看结果汇总。

## 11. 验收标准

1. 用户可以完成一次 PDF 题集导入，并在复核后生成题库。
2. 用户可以从题库中随机生成指定题数的考卷。
3. 用户提交单题答案后，App 立即显示该题答案和解析。
4. 客观题可以本地批改。
5. 主观题可以通过 AI 批改，并在失败时进入待复核状态。
6. 导入异常、题数不足、无标准答案和 AI 失败均有明确中文提示。
7. 所有题库、考卷和作答记录均保存在本地。
